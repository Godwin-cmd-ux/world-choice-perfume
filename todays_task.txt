## SECTION 1: Make WhatsApp and Email Contact Information Clickable

### Objective

Make the WhatsApp number and business email address displayed in the homepage's Contact Us section functional links that allow visitors to contact World Choice Perfumes directly.

### Instructions

1. Locate the Contact Us section on the public homepage.

2. Make the displayed WhatsApp number clickable.

3. When a visitor clicks the WhatsApp number, open a direct conversation with the correct World Choice Perfumes WhatsApp account.

4. Use the official WhatsApp click-to-chat URL format:

   `https://wa.me/PHONE_NUMBER`

   Replace `PHONE_NUMBER` with the actual business WhatsApp number already configured in the project. Use the international format with digits only, without a plus sign, spaces, brackets, or hyphens.

5. Make the displayed business email address clickable using a `mailto:` link.

6. Clicking the email address should open the user's configured email application with the correct business email address populated as the recipient.

7. Where appropriate, allow WhatsApp links to open the WhatsApp application on mobile devices or WhatsApp Web on desktop devices.

8. Preserve the existing homepage layout, contact icons, typography, colors, spacing, and responsive design.

9. Do not invent or replace the existing business contact details.

10. Inspect shared contact components and other relevant public-facing pages to determine whether the same improvement should be applied consistently elsewhere.

### Acceptance Criteria

* Clicking the WhatsApp number opens a direct chat with the correct business account.
* Clicking the email address opens an email composition window addressed to the correct business email.
* Both links work appropriately on desktop and mobile devices.
* Existing contact information and styling remain intact.

## SECTION 4: Add a Delete Action to the Customer Care Inquiry Section

### Objective

Allow authorized Customer Care users to delete inquiries that were created by mistake or are no longer needed.

### Instructions

1. Locate the Inquiry section in the Customer Care module.
2. Inspect the existing inquiry listing, detail page, database model, routes, controllers, services, and authorization rules.
3. Add a clearly visible **Delete** action to the appropriate inquiry interface.
4. Allow authorized users to delete an inquiry that was mistakenly created, incorrectly classified as an inquiry instead of a comment, or otherwise needs removal.
5. Implement deletion through the backend using the existing project architecture. Do not implement deletion as a frontend-only operation.
6. Follow the project's existing deletion conventions. If the system uses soft deletion, use that approach unless there is a documented reason to do otherwise.
7. Require user confirmation before deletion. For example, display a confirmation dialog asking whether the user wants to delete the selected inquiry.
8. Enforce authorization on the backend so that unauthorized users cannot delete inquiries by manipulating URLs, record IDs, or HTTP requests.
9. Handle missing records, validation failures, and server errors gracefully.
10. After successful deletion, update the inquiry list and display an appropriate success message.
11. If deletion fails, show a useful error message without falsely indicating success.
12. Inspect related replies, comments, attachments, audit records, and other relationships before selecting the deletion method. Avoid accidentally deleting unrelated records.
13. Do not automatically delete an inquiry because it was incorrectly classified. The authorized user must explicitly initiate the deletion.

### Acceptance Criteria

* Authorized Customer Care users can delete inquiries through the interface.
* A confirmation dialog appears before deletion.
* Successfully deleted inquiries no longer appear in the active inquiry list.
* Backend authorization prevents unauthorized deletion.
* Unrelated records and associated information are not accidentally deleted.
